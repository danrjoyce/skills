# Assessment and revision

Use for substantial changes, performance claims or adoption decisions. Scale the work to risk, reversibility and the evidence needed for the decision; this is not a mandatory benchmark for every skill.

## Contract before comparison

Record the artifact version, model/host, tools, permissions, task scope and evidence budget. Select relevant cases with required predicates, acceptable alternatives, evidence sources and critical gates. Include realistic near-negatives and missing prerequisites. For consequential operations, inspect the action trace as well as the final state: an unauthorized write later reversed still matters.

Choose the question:

- **Static readiness:** files, references and scripts are structurally usable under stated assumptions.
- **Fitness:** required outcomes and constraints are met in the tested envelope.
- **Incremental benefit:** an appropriate comparator, such as an existing helper or a concise instruction, does worse on the declared endpoint.
- **Adoption:** likely future benefits justify setup, operation, review, maintenance and risk for the intended user.
- **Superiority:** a frozen comparative design supports a scoped advantage with appropriate uncertainty. Neither nonsignificance nor a small observed tie establishes equivalence.

Report a vector of correctness, boundary behavior, effort and limitations. Critical scope/permission violations cannot be canceled by style or average-score gains. Unknown evidence is not a pass or a proven defect.

## Make the checks earn trust

For each important check, ask how a defective output could fool it. Test an independently derived valid output, a substantive defect and a valid noncanonical alternative. Parse exact formats mechanically; review meaning when correctness depends on entailment, omissions, audience or judgment. A valid citation ledger does not make false prose true. Calibrate judgment with anchored examples and preserve disagreements. Shared mistaken references can make multiple graders agree.

Assess selection and downstream execution separately. Record actual loading/resource events where visible; an agent claiming to have read a file does not prove it did. User-only skills need explicit-invocation tests. A host with no loader/executor is an unsupported integration, not evidence the package is ineffective.

Use inert adversarial text and disposable test state for source injection, unsafe defaults, uncertain retries or evaluator manipulation when relevant. Never execute suspected malicious code in an unrestricted environment to demonstrate danger. Incomplete action telemetry supports only observed compliance, not verified absence of prohibited actions.

## Learn without selecting the answer

Before optimization, identify development, selection and final-assessment data, the comparator, primary checks, cost/retry cap and stopping rule. Once a case influences instructions, selection, thresholds or the rubric, it is development/selection evidence for that choice. Freeze the chosen version before final assessment. Fresh conversation, hashes and a promise not to peek are not enforced isolation; disclose shared context or accessible evaluation files.

Use reset state and comparable information, tools and effort across methods. Preserve every creation/run attempt, missing result, failed revision and cost. Timeouts are operational outcomes. Allow technical reruns only under a declared cause/evidence rule, preserving the original. If the oracle is defective, stop affected scoring, fix/version it and regrade locked outputs rather than penalizing the solver.

Report creator production/routing separately from the performance of surviving generated skills. If creation fails or appropriately recommends an alternative, retain that assigned brief and its cost; any fallback success belongs to the declared fallback policy. Do not claim reliable generation from a single good survivor.

## Decide and maintain

Keep observed results tied to their finite tasks and runtime. Repeated variants do not add independent domains. Report uncertainty, unrun cases and important losses alongside gains. If missing evidence could change the decision, leave it inconclusive or recommend a bounded reversible trial where authorized. Stop when the declared decision is resolved, the budget is reached, or invalid evidence/critical risk blocks it; do not extend until a win appears.

On a demonstrated regression, isolate the failing requirement, change the smallest responsible component and rerun affected checks plus important preserved invariants. Record why the change generalizes beyond the one example. Before adoption, identify the maintainer, rollback artifact and triggers for review (host/model change, dependency change, new task population, incident or stale source). Retire redundant rules when a simpler workflow now suffices.
