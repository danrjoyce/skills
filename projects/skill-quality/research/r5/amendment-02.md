# R5 independent implementation review

2026-10-02. Clarifies R4 v0.1 and [amendment 1](amendment-01.md) before any model trial. The original protocol, schema, design manifest, task weights, baselines and spending/resource ceilings are preserved.

## Corrections supported by negative controls

1. **Git state versus cached stat bytes.** Ordinary `git status` can refresh `.git/index` filesystem-stat caches without changing staged content. Requiring identical index bytes would penalize permitted inspection. Compare staged paths, modes, blob IDs and flags with read-only `git ls-files --stage -v -z`, with optional locks and filesystem-monitor integration disabled. Other initial Git files, refs, logs and objects remain byte-protected. A staged source change and a changed HEAD both fail. This exception permits neither staging nor history changes. Unexpected index structure or unreadable state fails conservatively.
2. **Evaluator evidence cannot redefine its own baseline.** Scoring requires a separate trusted case directory. Solver-side fixture/start-state files are never authoritative; if included, their bytes must match the trusted copy. They can be omitted when staging solver inputs. The coordinator must compare that trusted copy to its pre-run inventory before and after scoring. Separate paths are not access controls in a shared filesystem. Symlinks and special files are rejected before artifact reads. Protected-state failure stops further artifact/code evaluation and remains a failure.
3. **Semantic reviews bind inputs and outputs.** W1 annotations identify the exact fixture, source/task inputs and output hashes. D1/R1 near-negative responses are captured by the evaluator outside solver state and included by hash. Routing-sentinel annotations likewise bind the request, contract and captured response. Missing, malformed, stale or mismatched reviews remain unknown. A valid annotation shape does not prove the reviewer competent or independent. Scope compliance still requires an appropriate action trace.
4. **Metadata and traces fail conservatively.** The local adapter rejects duplicate YAML keys, aliases, nonmapping sidecars, inconsistent invocation modes and symlinked roots/logs. The metadata profile is narrower than full YAML. Duplicate/malformed trace events cannot supply a complete-trace pass. These are file-interface checks, not hostile-code containment or proof every host access was logged.
5. **Ready records retain identities and physical costs.** Readiness requires source pins, frozen evidence roles, hash linkage, readable artifact bytes, an exposure record and a supervision snapshot. A selected package is identified by an inventory artifact with role `selected_package_inventory`. Shared fallback rows preserve the matched N0 status, predicates, violations, trace references and outputs, with zero physical execution cost and no added package. Token costs cannot be duplicated. A critical authoring violation cannot disappear through fallback. All five nonproduction dispositions are exercised by controls. Setup/coordinator qualification time counts toward its 120-minute allowance; it does not fabricate a model worker start. Every actual worker start still counts toward 112.
6. **Supervision is separate from the unchanged schema.** A sidecar supplies the campaign clock, actual worker-start attempt IDs (including any worker-based qualification), storage, submitted-package sizes, sequential-status evidence and source references. Downstream input identities must match the canonical frozen case manifest, not merely have a hash-shaped string. The validator detects 660-minute scheduling, 250 MiB storage, 2 MiB submitted-package and policy/campaign overruns. It checks declarations retrospectively; it neither stops a worker nor proves missing attempts, hidden events or omitted versions never existed. Unknown sequential verification stays explicit. R6 must inspect actual intervals, preserve every draft/revision and stop at the limits.

## Candidate freeze exception

The initial six-file candidate was frozen before detailed fixture implementation: [original freeze](candidate-freeze-original.json). Independent generic inspection found that `name/description` parsing used `\s*` after a colon, silently accepting a multiline YAML value despite claiming to check single-line values only. A standalone multiline-description control reproduced a false complete audit.

Only `scripts/inspect_package.py` changed: horizontal colon whitespace, indented-continuation detection, and conservative handling of implicitly typed or malformed quoted scalars. Expanded controls reproduced false-complete results for a nonempty multiline value, numeric and uppercase-boolean values, and malformed single quotes. These forms now require a full-parser review. The other five files, including every operative authoring instruction and reference, are byte-identical to the original freeze. The [revision freeze](candidate-freeze.json) records the reason, original identity and new inventory. This is a disclosed post-fixture-exposure helper repair, not a claim the final package was wholly authored blind. Neither version has been run through a model.

## Verification history

The first fixture-build test exposed nondeterministic Git index stat-cache timestamps; rebuilding the initial index from HEAD fixed it. The fresh review then exposed the distinction between those harmless later cache updates and real staged changes, leading to correction 1 above. A first combined unit-test discovery also imported the original test class twice, causing temporary-path collisions; removing the imported class from discovery fixed the test harness. Both are engineering failures retained here, not model failures.

The final local checks and remaining boundaries are recorded in [R5 verification](../verification-r5.md). No case outcome was used to revise candidate workflow instructions, no benchmark result was selected, and no superiority inference follows.
