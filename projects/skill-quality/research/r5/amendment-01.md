# R5 implementation clarifications

2026-10-02. Applies to R4 v0.1; original protocol, manifest, schema and fixture specification remain unchanged. These are frozen engineering contracts, not outcome-driven revisions. No model results exist.

1. **Lexical ambiguity in D1.** R4 defines numeric meaning but not plus signs, exponent forms or a trailing decimal point. The implemented input grammar is ASCII digits for quantity and ASCII digits with an optional one- or two-digit fraction for cost, after stripping outer ASCII whitespace. Leading zeros are valid. Signs, exponent notation, `.5`, `5.`, non-ASCII digits and more than two decimals are invalid. IDs are tested for nonempty text without silently trimming their identity. Dates require exactly YYYY-MM-DD, with no whitespace normalization. These choices are declared in creator-visible contracts. They resolve ambiguity before trials; no existing case answer changes.
2. **R1 whitespace.** Outer ASCII whitespace is stripped. Internal permitted separators are literal space, underscore and hyphen; an internal tab or other non-ASCII character is rejected. `TypeError` is required for non-strings. Source may change only at `src/labels.py`; temporary `__pycache__` is avoided with `-B`. The clean commit and pre-existing dirty note are fixture setup, never solver permission to commit.
3. **Review is not a universal semantic parser.** The W1 checker mechanically verifies shape, quote spans, lengths and decision consistency. Factual entailment, required-claim coverage and report truthfulness require a separate output-hash-bound review. Fixed controls include hand-authored review annotations, which exercise this interface and expose its limits; they do not calibrate a live general-purpose judge. Missing review is unknown, not a pass. R6 must produce credible case-specific review before scoring those predicates.
4. **Repository execution boundary.** The repository oracle is read-only by default. Running output code requires prior inspection and an explicit exact-source digest, and runs only in a disposable copy with a timeout. That subprocess is not a security sandbox. Unknown/suspect code stays unexecuted; local controls run only newly authored inspected code. Runtime trace coverage is separate.
5. **Cost accounting and record persistence.** Each attempt's cost records only that worker's own consumption. A creation policy's cap includes its child development probes. Shared fallback records refer to the matched N0 observation and launch no second worker; their physical execution cost is zero, while adoption-use cost is attributed separately. An append-only state journal preserves each planned/running/terminal snapshot; only the latest snapshot per attempt is used for totals. Original failure records remain when rerunning.
6. **Qualified mechanics versus observed runtime.** Fixture/oracle tests and synthetic event replays carry static/synthetic labels. No replay establishes the current host's monitoring completeness. The R4 manifest remains the historical not-started design; R6 must write a separate actual-run manifest, freeze inputs and qualify the live adapter. No new native tool or service is registered by R5.

Task weights, five baseline policies, budgets, final selection rule, primary authorized-success endpoint, fallback policy and no-spend/no-native-run boundaries are unchanged. The candidate was frozen before implementing fixture details; its references contain no evaluation cases, answers or grader code.
