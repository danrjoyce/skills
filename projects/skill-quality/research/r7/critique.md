# R7 independent critique: useful failure, insufficient comparison

2026-10-02. Reviewed remote commit `0e66e7eff6899f9e3082cbe9d67c3e9847966b1e` in a fresh context. This is an independent review of existing evidence, not an independent experiment. The accessible local archives were inspected without executing their code or following archived symlinks. No creator, solver, generated helper or semantic reviewer was rerun. [Review checks](evidence-review.json) and the [R6 status correction](r6-status-addendum.md) distinguish public evidence, local observations and unknowns.

## Decision

Keep the original candidate and R6 results frozen. Do not promote the candidate or claim any creator won. Proceed separately to a **smaller, practically usable v2 creator**, focused on the real starting state, authorized effects and an end-to-end first-use check. The next deliverable should be that creator, not another evaluation framework.

The ten public case outcomes are reproducible from the retained artifacts: N0 has two mechanically correct exports; C0, T0, O0 and A0 each have two missing-output failures. The diagnosis is credible: all four generated helpers reject the pre-existing output directory. But the creator-facing contract omitted its starting state and also said no overwrite. This is shared integration failure under an underspecified contract, not clean evidence that one creator's instructions are worse than another's. The direct solver result does not establish general superiority, amortized value, safety or reliability. ## Prioritized findings and acceptance criteria

### C1. High: distinguish a safe stop from a defective integration contract

The shared authoring contract names exactly three `output/` files. It does not say whether the directory exists. The answer bank says no overwrite. The frozen builder creates `output/` before every solver, and staging faithfully copies that state. C0 explicitly prohibits even an empty directory; T0 uses exclusive directory creation; O0 and A0 have equivalent existence guards. Their documented stop behavior therefore conflicts with the supplied state before an export can be delivered. The failure is in the composed workflow, regardless of whether their CSV arithmetic is otherwise correct. [Contract and answer-bank definitions](../r5/support/build_fixtures.py), [all four package sources](../r6/selected-packages.json), [diagnosis](../r6/report.md#diagnosis-of-the-eight-operational-failures).

Counterargument: the same state was used for every arm and was fixed before generation. This is a legitimate operational test, not post-hoc sabotage. Also, creating a new file in an authorized empty directory need not overwrite anything. A robust creator could distinguish directory existence from file collision. Nevertheless, equal staging does not make an unstated environmental assumption a clean test of creator quality. All methods received the same misleadingly incomplete interface. The lower-level solvers were right not to delete the directory, change the fixed paths, or patch their assigned packages to obtain a score.

Acceptance: v2 must recover or state material starting-state assumptions, distinguish authorized file creation from replacement, and avoid adding needless preconditions. Future file-writing briefs must explicitly distinguish absent directory, existing empty directory, occupied target and unsafe path. Empty-directory support is appropriate when authorized; refusal remains correct for a real collision or uncertain authority. Do not teach blanket overwrite, delete-and-recreate, silent relocation or universal acceptance of existing paths. The old fixture and all scores stay unchanged.

### C2. High: the primary gate is honest, but the claimed supervision must stay narrower

The host cannot expose authoritative child calls, exact model identity, complete actions or per-boundary cancellation. Blocking the original protocol rather than silently substituting explicit loading was sound. The separately declared diagnostic asked a narrower answerable question and retained every fixed assignment. Its observed outputs are useful despite missing cost/safety telemetry. A perfect causal infrastructure is not a prerequisite to learning that a workflow cannot start. [Preflight](../r6/preflight.json), [diagnostic protocol](../r6/diagnostic-protocol.md).

However, R6 did not verify every cap. The last published setup snapshot predates the stop. The later local record puts the conservative 120-minute setup bound at about 20:01:43 UTC and publication termination at 20:02:15, approximately 32 seconds later. This is an overshoot of the conservative accounting bound, not a measured active-computation overrun. The original loading qualification also has a 225.155-second journal running-to-terminal-record interval against a 120-second ceiling, without separate admission/completion times. Neither interval can certify runtime compliance. The semantic reviewer has its separately disclosed 244-second observed interval against 240. The frozen consistency check compares an earlier snapshot to the limit, so its pass does not establish end-of-publication compliance. [Supervision](../r6/supervision-final.json), [frozen checker](../r6/verify.py), [journal](../r6/journal.jsonl), [status addendum](r6-status-addendum.md).

Acceptance: preserve all unknowns and stop evidence, retain the original cumulative campaign counts and clocks, and never reset them through a new context. A later, genuinely separate campaign must declare feasible controls before launch, including publication/recording headroom and a conservative stop that does not wait until the boundary. Review and implementation can proceed separately without pretending the completed experimental campaign resumed or recovered budget. Do not require unavailable full telemetry for a modest artifact-only question; do require it for claims that depend on it.

### C3. High: the candidate needs an operational improvement, not more research paperwork

The candidate is six files and 22,273 bytes, with a 904-word entrypoint. It already asks for a benign case, relevant boundary, near-miss trigger, missing prerequisite, hostile input, significant-rule review, source triage, costs and maintenance. Yet its generated package's extensive self-checks reinforced the wrong destination assumption. Additional generic instructions to be careful or test thoroughly would duplicate what failed to help. Author check counts of 40, eleven, sixteen and thirteen use incompatible grouping and are not evidence that more checks improved utility. [Candidate](../../candidate/evidence-skill-creator/SKILL.md), [candidate assessment reference](../../candidate/evidence-skill-creator/references/assessment.md), [creation outcomes](../r6/report.md#creation-outcomes-and-selection).

Counterargument: most detailed material is conditionally loaded and the entrypoint repeatedly asks for proportionality. The inspector performs useful deterministic packaging checks. File count or length alone does not prove over-engineering. There is no measured causal link from its length to the failure. The criticism is practical: the default authoring path is still carrying an evaluation agenda while missing one concrete first-use condition.

Acceptance: make the normal path short enough to follow directly: decide whether a skill is useful; establish inputs, starting state, outputs and authority; build the smallest useful package; run one realistic first use plus the boundary most likely to invalidate it; report what worked and what remains unknown. Put comparative research, provenance ledgers and extensive adversarial evaluation behind a real decision/risk trigger. A typo or small low-risk edit must not require a research record, an ownership ceremony or a battery of unrelated probes. Keep or reuse the inspector only if it earns its place; do not grow a second test platform.

### C4. High: the observed loss is real, but its unit and scope are very small

There is one generated package per creator, used on two public CSV cases sharing the same destination condition. Eight failures are not eight independent creator failures; the two rows of results mostly repeat one integration failure for each package. These cases cannot estimate variability across generations, domains or future deployments, nor distinguish the four creator methods that all stop at the same gate. The fixed denominator and no-retry policy prevent selective removal of losses, which is a strength. [Protocol](../r6/diagnostic-protocol.md), [results](../r6/diagnostic-results.json).

The direct solver also solves a different practical burden: it constructs a tiny six- or eight-row answer now; a creator pays authoring cost for repeated future exports. N0's edge result was manually transcribed according to its retained local report. This is a legitimate no-added-package control, but two tiny tasks do not show which policy is preferable for repeated or large exports. No break-even calculation is possible without measured repeated-use effort and realistic workload assumptions.

Acceptance: retain the exact finite-task result and label the cases as known development evidence for v2. Do not pool them with future results or retest them selectively as holdouts. A later small usefulness diagnostic should include a real second-use situation and another workflow family, with the concise template and direct solution retained as serious alternatives. Declare the decision and minimum useful gain first; do not restart all 84 cells merely because that plan exists, or expand until a win appears.

### C5. High: final artifacts support correctness, not a full authorized-action history

The unchanged input hashes, final scope predicates, actual adapter-read records, package source guards and attributed command failures agree with the reported diagnosis. That is strong narrow evidence. But a returned file inventory cannot reveal a transient prohibited action later undone, a read outside scope or an unobserved network request. N0's ordinary transient JavaScript source is not retained as coordinator-observed evidence. This matters for claims about code inspection and actions even though its output is correct. The public source/runtime archive publication was denied; local access in this review does not make it publicly reproducible. [Trace/scoring implementation](../r6/diagnostic-runner.py), [publication boundary](../r6/report.md#publication-boundary), [retention manifest](../r6/retained-evidence-manifest.json).

Counterargument: demanding perfect telemetry to credit a correct CSV would erase valid evidence. The current split handles this properly: artifact correctness passes for N0, authorized success stays unknown; the generated arms fail the aggregate on missing artifacts, not established safety misconduct. Preserve that distinction.

Acceptance: future minimal capture should retain the exact command/script text that actually produces outputs, its exit/result, starting-state manifest including relevant directories, output bytes and source identity at the time. Use a feasible supported evidence destination agreed before launch. Do not retry or re-encode the denied archives through another channel. If complete action capture is still unavailable, keep the endpoint artifact-only and avoid safety-rate or verified-supervision claims.

### C6. Medium: A0 selection is defensible, but production is not completed author reporting

R4's last-completed-draft rule permits retaining A0's six-file initial package when later reporting is interrupted. The bytes match the initial snapshot; one permitted sequential development solver is counted; no replacement author, final-case coaching or best-of selection occurred. This is preferable to converting a reporting timeout into a fictitious package failure or granting free finishing time. [R4 selection rule](../comparative-protocol.md#32-common-adaptation-feedback-and-selection), [A0 journal records](../r6/journal.jsonl), [selected package](../r6/selected-packages.json).

The phrase `completed_creator_episodes: 4` in the manifest is easy to overread. It means four episodes reached terminal disposition and four packages were selected, not that four authors completed every requested deliverable within all measured budgets. A0 has no creator report and an unknown final call total; 17 author calls plus four development calls is only the last attributed subtotal. The development solver's new-directory success does not test the failed destination state. [Manifest](../r6/actual-run-manifest.json), [cutoff explanation](../r6/report.md#a0-cutoff).

Acceptance: use separate labels for package produced, author/report completed, selected version and budget compliance. Keep missingness rather than invent a report. A later comparison must predeclare how missing reporting affects eligibility, without retroactively disqualifying this already selected artifact or claiming known final-call compliance.

### C7. Medium: baseline source fidelity does not restore native workflow fidelity

The pinned closures and licenses are complete and independently hash-checked. This addresses a genuine earlier prerequisite. But A0 lost human/graphical feedback and its native optimization loop; both public creators ran through an adapted file reader in a shared host. Equal restrictions are not equal impairment when methods rely on different facilities. Allowing A0 one development solver within the common budget is not an unfair extra generation; it is a predeclared available capability. [Baseline inventory](../r6/baseline-inventory.json), [adaptation](../r6/diagnostic-protocol.md#equal-common-host-adaptation).

Acceptance: name the intervention as a constrained common-host adaptation whenever presenting the comparison. A later native-system study would measure creator plus host plus model, not isolate creator wording. No paid services, installation or native-host study follows from this review. Keep the concise template comparator: a sophisticated candidate has to justify itself against a cheap, usable alternative, not just famous package names.

### C8. Medium: shared background capabilities are part of the treatment envelope

Both N0 solvers report generic spreadsheet guidance; they were never a bare model. All solvers had the same background catalog and three neutral entries, while generated-package solvers had an additional explicit-load path and their package's restrictive instructions. Reading, counting and reporting overhead consumes some common call budget. That overhead is legitimate for a deployment-policy question, but it is not a pure comparison of arithmetic ability or underlying model intelligence. Exact backend model equality is also unverified. Shared readable evaluator files mean the clean-context rule is hygiene, not custody. [Diagnostic protocol](../r6/diagnostic-protocol.md), [solver prompt construction](../r6/diagnostic-runner.py), [report](../r6/report.md#diagnosis-of-the-eight-operational-failures).

Acceptance: state the background capability envelope and observed loading by category, without copying private instructions. Keep the endpoint tied to the actual policy and distinguish incidental evaluation overhead from useful runtime work where observable. Do not infer contamination actually occurred solely because it was possible; do not label the test blind or isolated solely because no worker reported it.

### C9. Medium: the semantic check detects two chosen defects, not general judge reliability

The reviewer matched eight expected predicate labels on four controls, accepting valid alternative organization and rejecting false prose and an irrelevant exact quote. Hash recomputation and coordinator review bind the annotations to actual content. This is useful evidence that the interface can capture the intended distinctions. It is not eight independent samples, an error rate, inter-rater reliability or general judge qualification. The controls and expected labels were accessible, one reviewer was used, and obvious authored defects offer limited coverage. No disagreement required adjudication. [Plan](../r6/semantic-qualification-plan.json), [annotations](../r6/semantic-annotations.json), [result](../r6/semantic-qualification-result.json).

Acceptance: keep the description as a four-public-control annotation check with timing uncertainty. Do not expand semantic grading for the next implementation task unless an actual output requires it. Later semantic claims need task-relevant harder cases, valid noncanonical alternatives, source/output binding and a declared disagreement procedure; independence must reflect real custody rather than neutral labels alone.

The local journal's final stop append was not in that remote commit. The published verification file's prospective tracking-check wording also did not record the eventual stop. These are stale status surfaces, not grounds to rewrite results. Acceptance: this review supplies the correction and updates current navigation and PR status while preserving all R6 artifacts. Exact-commit zero checks means absent CI, never passed CI. The next task must respond to C1-C10 and produce v2, with accepted, partially accepted, deferred or rejected dispositions and evidence. Marking every issue solved through prose is insufficient: empirical questions remain deferred until suitable new evidence exists.

## Proportionate next stage

Create `candidate/evidence-skill-creator-v2/` as a separate research artifact. The old package remains the frozen comparator. Make a materially shorter entrypoint, preserving useful trigger boundaries, authorization limits, source handling and honest unrun/failure reporting. Prefer the entrypoint plus required invocation metadata; add only resources that remove repeated work. Comparative research can live outside the runtime path. Do not embed CSV schemas, this experiment's method labels, scores or fixture answers.

The key addition should generalize: **test the consumer's actual starting state and promised result, not just a helper in the author's convenient workspace**. For file output, a directory's existence and a target-file collision are different facts. For other workflows, the analogous state might be an existing draft, a dirty repository or a missing prerequisite. This is a reasoned design proposal from observed failure, not a measured cure.

R8 acceptance is a usable v2 artifact, a compact C1-C10 response, a new immutable inventory, relevant static checks and a clearly scoped proposal for any later live assessment. A shorter file is a design constraint, not a quality score. If simplification would delete an important permission or correctness boundary, preserve it and explain the tradeoff. Do not launch a new experimental campaign during that implementation task. The [exact next-context prompt](continuation.md) makes the boundary explicit.

After v2 is frozen, fresh evidence would be needed to claim it improves usefulness: declared new authoring briefs with unambiguous starting-state contracts, fixed comparators and denominators, known-example regression checks clearly separated from new-case assessment, feasible resource supervision and the intended repeated-use benefit. Broad superiority, reliable safety, cost dominance, equivalence and native-host effectiveness all remain unproven. A good outcome may still be a concise template or no added skill.
